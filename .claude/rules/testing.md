# Testing rules

- Inspect project scripts and existing test conventions before choosing commands or frameworks.
- Add/update tests for bug fixes, business rules, and meaningful behavior changes.
- Cover important success, loading, empty, error, and validation states.
- Prefer stable tests that verify behavior over brittle tests tied to implementation details.
- Do not claim checks passed unless they were executed and passed.
- Report exact checks run, results, and any environment limitation.
